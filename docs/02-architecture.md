# Архітектура генератора

Рішення, зафіксовані для першої версії (v1).

## 1. Вихідний формат: PDF

v1 віддає **тільки PDF**. Не Figma, не сайт.

Наслідок для всієї системи: **проміжний формат — HTML + CSS**, PDF друкується
з Chromium через Playwright. Це не компроміс, а найдешевший шлях:

- секції типу `diagram` (25 з 74) верстаються звичайним HTML/CSS/SVG — жодних
  графічних бібліотек, охоронне поле й типографічна шкала це просто розмітка;
- секції типу `composite` (15 з 74) — це згенерований фон як `background-image`
  плюс **SVG логотипа поверх засобами CSS**. Логотип лишається векторним і точним,
  бібліотека композитингу (sharp/ImageMagick) не потрібна взагалі;
- той самий HTML пізніше стає веб-версією брендбуку без переписування.

### Обмеження, яке треба знати заздалегідь

Chromium друкує **лише RGB**. Отриманий PDF — екранний/презентаційний.
Для передачі в друкарню (CMYK, Pantone, вильоти, мітки різу) потрібен окремий
маршрут постобробки — у v1 його немає. Тому в брендбуку CMYK/Pantone коди
**друкуються як текст** (секція `color.codes`), але сам PDF у типографію не йде.

## 2. AI-провайдер: OpenRouter

Єдина точка доступу до моделей, один ключ, один білінг.
Ключ у `.env` (`OPENROUTER_API_KEY`), файл у `.gitignore`.

### Моделі для зображень

Перевірено запитом до `/api/v1/models` (28.07.2026) — 11 моделей з `image` в
`output_modalities`:

| Модель | Ціна за токен зображення | Роль у проєкті |
|---|---|---|
| `google/gemini-3-pro-image` | $0.00012 | герої, обкладинка, ключові мокапи |
| `google/gemini-3.1-flash-image` | $0.00006 | основний робочий кінь |
| `google/gemini-2.5-flash-image` | $0.00003 | масові прев'ю, чернетки |
| `google/gemini-3.1-flash-lite-image` | $0.00003 | найдешевші ітерації |
| `openai/gpt-5-image` | $0.00004 | альтернатива, коли Gemini не тримає стиль |
| `openai/gpt-5-image-mini` | $0.000008 | дешеві варіації |
| `openai/gpt-5.4-image-2` | $0.00003 | альтернатива |

Ціна вказана за **токен**, не за картинку. Одне зображення — приблизно 1.3k
токенів, тобто орієнтовно $0.04 за Gemini 2.5 Flash і ~$0.15 за Gemini 3 Pro.
**Реальну вартість зафіксувати на першому прогоні** — і після цього
порахувати бюджет одного брендбуку.

Стратегія: чернетки на дешевій моделі, фінал — на Pro, з кешуванням у `.cache/`
за хешем промпту, щоб перезбірка PDF не оплачувалась повторно.

### Чого OpenRouter не вміє

**Відео.** Жодної моделі з відеовиходом. Це впливає на реєстр секцій:

- `motion.logo` і `motion.video-style` у v1 виконуються не як відео, а як
  **розкадровка**: 4–6 згенерованих кадрів у ряд + опис таймінгів і easing.
  Для PDF це і є правильна подача — відео в PDF все одно не програється.
- Якщо відео знадобиться для веб-версії, потрібен другий провайдер
  (у цій сесії доступний Higgsfield MCP), але це поза скоупом v1.

### Текст

Текстові секції (31 з 74) — теж через OpenRouter, звичайний chat completions.
Модель обирається окремо від зображень; стратегічний блок вимагає сильної моделі,
бо його вихід стає входом для всіх промптів генерації візуалу.

## 3. Пайплайн

```
input/          бриф, логотип, фото, референси, шрифти
   ↓
[1] BRIEF       нормалізація вхідних даних → brief.json
   ↓
[2] STRATEGY    LLM: суть, позиціонування, архетип, TOV → strategy.json
   ↓            (критично: живить усі промпти далі)
[3] TOKENS      колір з логотипа, шкала, контраст → tokens.json + tokens.css
   ↓            (детерміновано, без AI)
[4] PROMPTS     strategy + tokens + референси → промпт на кожну image-секцію
   ↓
[5] GENERATE    OpenRouter → PNG у output/assets/, кеш за хешем промпту
   ↓
[6] COMPOSE     HTML-шаблон на секцію + tokens.css + асети
   ↓
[7] RENDER      Playwright → Chromium print → brandbook.pdf
```

Кроки 1–3 дешеві й детерміновані, крок 5 — єдиний платний.
Кроки 6–7 можна ганяти нескінченно безкоштовно, доки готові асети.

## 4. Стек

- **Node.js 24** (є в системі)
- **Playwright** — рендер PDF
- **HTML/CSS** — шаблони секцій, CSS `@page` для полів і колонтитулів
- **fetch** — OpenRouter API, без SDK
- Без фреймворків. UI з чекбоксами — статична сторінка поверх
  `data/brandbook-sections.json`.

## 5. Структура репозиторію

```
data/     brandbook-sections.json    реєстр 74 секцій — джерело правди
docs/     анатомія, архітектура
input/    матеріали клієнта (у .gitignore, крім .gitkeep)
  brief/       текстовий бриф
  logo/        SVG/AI логотипа — ніколи не генерується
  photos/      реальні фото продукту й команди
  references/  візуальні референси
  fonts/       ліцензійні шрифти
output/   згенеровані асети й готовий PDF (у .gitignore)
```

## 6. Наступні кроки

1. Схема `brief.json` — які питання ставимо клієнту
2. Крок TOKENS: витяг палітри з логотипа + розрахунок контрасту
3. Один шаблон секції наскрізь (`logo.clearspace`) → PDF, як доказ пайплайну
4. Прогін одної image-секції для замірювання реальної вартості
5. Веб-UI з чекбоксами
