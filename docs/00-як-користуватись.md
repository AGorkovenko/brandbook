# Як зробити брендбук

Покрокова інструкція від «є компанія» до «є PDF».

## Один раз: налаштування

```bash
npm install
cp .env.example .env
```

У `.env` вписати ключ з [openrouter.ai/keys](https://openrouter.ai/keys):

```
OPENROUTER_API_KEY=sk-or-v1-...
```

## Найпростіший шлях: інтерфейс

```bash
node src/cli.js ui
```

Відкриється `http://localhost:4000` — чотири вкладки, які ведуть від матеріалів
до PDF.

> **Не відкривайте `web/index.html` подвійним кліком або через вбудований
> сервер IDE.** Сторінці потрібен локальний сервер, який читає й записує файли
> проєкту — без нього вона лише покаже підказку із цією командою. Якщо сервер
> уже запущено, сторінка з IDE знайде його на порту 4000 сама.


1. **Матеріали** — перетягніть файли, вони самі розкладуться по папках
   (`.svg` → логотип, фото → photos, тексти → brief). Папку можна змінити
   перед завантаженням.
2. **Бриф** — форма з усіма полями. Кнопка «Скласти з матеріалів» заповнює її
   автоматично; блок «Що система домислила» показує припущення з чекбоксами
   «згоден».
3. **Секції** — 74 чекбокси по групах, пресети одним кліком, лічильник сторінок.
4. **Збірка** — стеля витрат, живий лог і посилання на готовий PDF.

Далі — те саме через термінал, якщо інтерфейс не потрібен.

## Крок 1. Скласти матеріали

```
input/logo/         логотип у векторі (.svg)      ← обов'язково
input/brief/        тексти про компанію (.txt, .md)
input/photos/       реальні фото продукту, команди, виробництва
input/references/   приклади, які подобаються
input/fonts/        ліцензійні шрифти
```

**Логотип обов'язковий і має бути SVG.** Знак AI не генерує — його неможливо
відтворити точно, тому він береться лише з вашого файлу. З SVG система заодно
витягує фірмові кольори автоматично.

У `input/brief/` кладіть що є: сторінку «про нас», описи послуг, пости,
відповіді на питання клієнтів, комерційну пропозицію. Не треба нічого
причісувати — сирі тексти навіть кращі, бо в них видно справжній голос.

## Крок 2. Скласти бриф

```bash
node src/cli.js brief:extract --url https://ваш-сайт.com
```

Система читає матеріали й складає `input/brief/brief.json`.

Що вона робить:
- **факти не вигадує** — якщо в матеріалах немає сайту чи тагляйна, поле лишиться порожнім;
- **характер виводить** — архетип, тон голосу, цінності, аудиторії;
- усе виведене пише в `meta.assumptions` з поясненням, з чого саме.

Коштує ≈ $0.10.

## Крок 3. Перевірити бриф ← найважливіше

Відкрийте `input/brief/brief.json` і перегляньте блок `meta.assumptions`.
Там перелічено все, що система домислила за вас.

Для кожного припущення:
- **згодні** → поставте `"confirmed": true`
- **не згодні** → виправте значення у відповідному полі

Особливу увагу:

| Поле | Чому важливе |
|---|---|
| `brand.personality` | найпряміше впливає на стиль усіх візуалів |
| `product.priceSegment` | одним словом задає щільність, кольори, фактури |
| `visual.avoid` | стає забороною в промптах генерації |
| `market.notLike` | те саме, від протилежного |
| `audience[].who` | визначає типажі людей на згенерованих фото |

**Непідтверджені припущення друкуються в готовому брендбуку окремою сторінкою.**
Це навмисне: замовник має бачити, що система домислила.

Перевірити коректність:

```bash
node src/cli.js brief:validate
```

## Крок 4. Зібрати брендбук

```bash
node src/cli.js build --budget 2
```

На виході:

```
output/brandbook.pdf     готовий документ
output/brandbook.html    те саме в HTML
output/tokens.json       палітра, шкала, сітка
output/tokens.css        CSS-змінні для сайту
output/strategy.json     стратегія бренду
output/costs.jsonl       журнал витрат
```

`--budget` ставить стелю витрат: збірка зупиниться, якщо перевищить.

## Що вже працює і що ні

**Готово:** структура документа, стратегія, тексти всіх секцій із правилами,
палітра з кодами HEX/RGB/CMYK, матриця контрасту WCAG, типографічна шкала,
охоронне поле, мінімальні розміри, сторінка припущень.

**Ще не готово:** генерація зображень — фотостиль, ілюстрації, патерни, іконки
й мокапи носіїв. Ці сторінки поки виходять із текстом і правилами, але з
поміткою «візуал ще не згенеровано». Механізм накладання логотипа на мокапи
вже перевірено (див. [`04-mockups.md`](04-mockups.md)), лишилось під'єднати
генерацію.

## Скільки коштує

Заміряно на реальному прогоні (пресет `standard`, 51 секція, 54 сторінки):

| Крок | Модель | Ціна |
|---|---|---|
| Витяг брифу | Claude Opus 4.8 | $0.10 |
| Стратегія | Claude Opus 4.8 | $0.08 |
| Тексти сторінок (5 батчів) | Claude Sonnet 4.6 | $0.65 |
| **Разом (без зображень)** | | **≈ $0.85** |

Тексти дорожчі, ніж здається: у кожен батч передається вся стратегія,
тож вхідних токенів багато. Це місце для оптимізації.

Повторна збірка бере відповіді з кешу і не коштує нічого — можна скільки
завгодно правити верстку. Щоб перегенерувати тексти заново, додайте `--no-cache`.

## Типові проблеми

**«Немає OPENROUTER_API_KEY»** — не створено `.env`.

**Палітра дефолтна замість фірмової** — у `input/logo/` немає `.svg`.
Растровий логотип (PNG, JPG) не підходить: з нього не витягнути ні кольори,
ні чіткий контур для друку.

**Бриф не проходить валідацію** — команда друкує конкретні поля.
Мінімум для запуску: назва, галузь, що продаєте, одна аудиторія, пресет.

**Тексти надто загальні** — замало матеріалів. Додайте в `input/brief/`
живі тексти: пости, листування з клієнтами, відповіді на заперечення.
Система пише тим краще, чим конкретніші вхідні дані.
